# Procurement-form decision checks

Use these synthetic requests to review the updated skill route. They require no real records, external messages, or application access. Evaluate the saved-field and workflow decisions, not whether an answer repeats the skill wording.

| Request or source condition | Required decision and completion evidence | Failure |
|---|---|---|
| Write a vendor quotation using the supplied business details and stamp. The user supplies the actual quotation date. | Proceed with preparation; treat the request as cleared with the vendor. Preserve the supplied date and stamp. | Asking whether the vendor allowed preparation or stamp use again. |
| A required amount is absent from both the request and available files. | Search the sources, then ask only for that essential factual value or leave an optional field blank. | Inventing an amount, or turning the factual question into a permission check. |
| All specification cells must follow `품목명 규격×수량 등`; the user says to remove only `○건` from `등 ○건`. | Extract every target row after saving. Every row retains item, specification, physical quantity, and `등`; every rejected count suffix is absent. | One row omits its item, substitutes a reference phrase, ends with a count, or removes `등`. Correct totals do not pass this row check. |
| The user requests a filled black confirmation box and `법인카드(4321)`. Other checkboxes are unmarked. | Only the requested box becomes `■`. The identifier reads as complete `4321` in the current page image. | A hollow box, a tick, an altered unrelated box, missing identifier, or digits split over lines. |
| Class-date A has goods, process, and results; class-date B has goods and results only. | Use the same goods-to-results order and emphasis for each date. Include A's process in the common smaller position; omit B's unavailable process. | Mixing dates, giving only one date a whole-session collage, or generating B's missing photograph. |
| The actual quotation date precedes preapproval; purchase dates group the quotation files. The quotation issuer differs from the actual merchant. | Preserve the actual issue date in each requested quotation. Keep purchase-date grouping and actual merchant receipt/payment records distinct. | Substituting today's date or purchase date for the quotation date, or changing the actual merchant to the quotation issuer. |
| The user requests editable Word quotations, with no PDF or review bundle requested or required. | Produce editable DOCX item tables; the supplied stamp may be an image. Use page images or minimum temporary verification PDFs outside active records. | Flattening the quotation into a page image, replacing it with a calculation sheet, or delivering unsolicited PDF copies. |
| Receipt scans are item references; the user will attach physical originals. A remarks cell is empty. | Use scans for source item data and preserve attachment areas. Leave the unneeded remarks cell empty. | Inserting reference scans as submitted receipts or adding a manual-attachment/process note. |
| The user has corrected the current file and asks to update skills only. | Inspect the correction read-only, improve the failed invocation or saved-file gate, validate, and publish public-safe skill changes when required. | Resaving the reference, rebuilding from an old draft, or claiming completion after an apology without a skill update. |
| A material-name cell lists items A and B followed by `등`, but its quantity cell covers only A. Other rows use the same format. | Fail the cross-column coverage check. Include A and B's supported specifications and quantities; repeated names may be omitted only when the order remains unambiguous. | Passing because the column format is uniform, the total matches, or `등` appears. |
| The plan must follow three quotations, while its source table has four receipt-merchant rows. Two component rows belong to one quotation. | Create three planned rows with quotation-matched amounts and the requested planned vendors. Sum the merged components; preserve the four actual receipt associations. | Keeping four plan rows by habit, copying actual merchants into requested planned vendors, or merging receipts as though the actual merchant changed. |
| The attached operating plan matches three quotations, but the official-letter cover table still has four purchase rows. Both tables have the correct overall total. | Fail the packet grouping check until every planned-purchase table has three data rows in quotation order with the matching amount vector. Preserve the separate receipt-merchant associations. | Checking only the attached plan or the overall total and leaving the cover table's old grouping. |

The entrypoints must route procurement work to the reference before filling and to the complete-column and field-map checks after saving. A parsing pass, total amount, or expected page count alone cannot satisfy these cases.
