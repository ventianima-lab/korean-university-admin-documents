# HWPX 인터넷 비교견적

인터넷 비교견적 문서를 만들 때는 `hancom-hwpx-documents`의 보존·검증 절차를 함께 적용한다. 후속 편집을 시작할 때마다 작업 폴더를 다시 확인하고, 현재 최종본이 있으면 그 파일을 내용·시각 기준으로 삼아 작업 전 사본을 보존한다. 더 최신인 최종본이 있는데도 이전 구성요소, 중간본, 백업본, 검증본 또는 과거 실행 산출물에서 문서를 다시 만들지 않는다. 최종본을 교체하기 전에는 기존 최종본의 해시와 페이지 수, 이미 반영된 견적·수량·금액·사진을 후보와 대조하고, 새 요청과 무관한 기존 내용이 하나라도 빠지면 덮어쓰지 않는다.

## 비교견적 성립 조건

- 본견적과 비교견적은 제조사, 모델명, 규격, 구성품, 선택 옵션과 수량이 같아야 한다.
- 비교견적은 본견적과 다른 판매처에서 확보한다.
- 비교견적 화면의 최종 총액은 본견적의 최종 총액보다 높아야 한다.
- 판매처만 다르고 제품 조건이 완전히 같은 견적을 사용한다. 다른 제품, 유사 모델, 다른 구성 또는 다른 수량으로 대체하지 않는다.
- 조건을 충족하는 화면을 찾지 못하면 다른 제품으로 채우지 말고 `비교견적 확보 실패`로 보고한다.

사용자가 동일 제품이 없는 품목의 유사제품 대체를 명시적으로 허용한 경우에만 예외를 적용한다. 구매할 본견적 제품은 유지하고, 비교 제품의 실제 브랜드·모델·포장과 주문수량을 그대로 적는다. 같은 용도·필수 규격·총중량 또는 총수량을 비교 기준으로 삼고 차이와 미확인 조건을 짧게 표시한다. `유사제품`을 명시하며 동일 제품 검증으로 통과시키지 않는다. 실제 비교 가격이 더 낮아도 가격을 고치거나 숨기지 않는다. 이 예외의 승인 근거, 기준, 차이, 실제 양쪽 수량·가격·출처는 [유사제품 검증 명세](references/equivalence-manifest.md)에 기록한다.

## 캡처 기준

각 캡처에는 다음 정보가 한 화면에서 확인되어야 한다.

- 판매처 또는 쇼핑몰 식별 정보
- 정확한 상품명과 모델명
- 해당 상품의 실제 제품 또는 포장 사진
- 선택한 규격·구성·옵션
- 본견적과 같은 선택 수량
- 해당 수량의 최종 총액
- 배송비가 총액에 영향을 주면 배송비 또는 무료 배송 표시

단가만 보이거나 수량 선택 전 화면, 장바구니 합계가 가려진 화면, 쿠폰 적용 여부가 불분명한 화면은 완료 증빙으로 사용하지 않는다. 사용자가 캡처를 제공했으면 새로 검색하기 전에 제공된 화면부터 검사한다.

- 수량을 입력한 직후의 이전 합계를 찍지 않는다. 선택 수량과 갱신된 상품 합계가 모두 맞는지 확인한 뒤 배송비·실제 적용 할인으로 결제금액을 계산한다. `개입`은 포장 구성 수이며 포장에 기재된 총중량과 혼동하지 않는다.
- 촬영 직전에 포인터를 견적 내용 밖의 빈 여백으로 옮기고, 호버 설명·선택 강조·클릭 표시를 해제한다. 캡처와 최종 PDF에서 포인터·클릭 테두리·강조가 발견되면 다시 촬영한다. AI 지우기나 픽셀 덧칠로 금융 증빙을 보정하지 않는다.
- 원본 화면은 보존하고 삽입용 사본은 필요한 부분만 충실하게 자른다. 상품 사진·상품명·선택 옵션·수량·가격·배송비는 모두 남긴다. 가격·수량 열만 잘라 상품 사진을 없애지 않는다. 사진과 결제정보를 각각 충실하게 잘라 같은 쪽에 배치할 수 있으나, 같은 상품·선택 조건의 원본인지 확인한다. 서로 다른 스크롤 위치의 화면을 이어 배치할 때 각 화면의 같은 제품·옵션·수량을 확인한다. 비정상 타일·중복·잘림이 있는 전체 화면은 그대로 쓰지 않는다.

## HWPX 작성 규칙

1. 품목별로 `본견적 → 비교견적 1 → 비교견적 2` 순서를 유지한다. 사용자가 요구한 비교견적 수가 다르면 그 수를 따른다.
   - 한 문서에 품목이 여러 개면 한 본견적 쪽에 합치지 말고, 첫 품목의 본견적과 비교견적을 끝낸 뒤 다음 품목의 본견적과 비교견적을 배치한다.
2. 각 그림 바로 위에 다음 형식의 편집 가능한 한글 문단을 둔다.
   - 본견적: `품목 | 제조사 모델명·구성 | 수량 N개 | 총액 N원 | 출처 쇼핑몰명`
   - 비교견적: `비교견적 1 | 품목 | 제조사 모델명·구성 | 수량 N개 | 총액 N원 | 출처 쇼핑몰명`
   - `출처`에는 `제조사 공식몰`, `네이버쇼핑`, `11번가`, `쿠팡`, `GS SHOP`처럼 문서만 보고도 판매 경로를 구분할 수 있는 명칭을 쓴다. 오픈마켓 안에서 판매자 구분이 필요하면 `11번가(판매자명)`처럼 병기한다.
3. 설명문을 캡처 이미지에 합성하거나 이미지로 만들지 않는다. HWPX 본문에서 선택·수정할 수 있는 실제 텍스트여야 한다.
4. 캡처 이미지는 비율을 유지하여 축소하고 `글자처럼 취급`을 켠다. HWPX XML에서는 해당 `hp:pic`의 `hp:pos`에 `treatAsChar="1"`, `flowWithText="1"`이 있어야 한다.
5. 가격, 수량, 상품명 또는 판매처가 잘리지 않도록 한다. 증빙 내용이 흐려질 정도로 축소하지 않는다.
6. 한 쪽에 비교견적 두 건을 넣어도 되지만, 두 설명문과 두 캡처가 모두 읽힐 때만 허용한다. 그렇지 않으면 쪽을 나눈다.
7. 기존 양식의 여백, 글꼴, 문단 간격과 품목 순서를 유지한다. 빈 쪽이나 캡처와 설명문이 분리된 쪽을 남기지 않는다.
8. 한컴 변환 또는 PDF 출력에서 캡처의 투명 영역이나 검은 픽셀이 페이지 배경으로 번지는 현상을 막기 위해, 삽입용 사본은 흰 배경의 RGB 이미지로 평탄화한다. 원본 캡처는 별도로 보존한다.
9. 사용자가 `세로`를 지정하면 A4 세로 방향을 문서 속성에 명시하고, 설치된 한글에서 변환한 최종 PDF의 모든 쪽이 세로인지 직접 확인한다.
10. 품목명·모델이나 구성·수량·금액·출처처럼 견적 판단에 필요한 정보만 표시한다. 비고란은 배송비 포함 여부처럼 합계를 해석하는 데 꼭 필요한 조건이 있을 때만 사용하고, 검색 과정·검증 결과·선정 이유·가격 변동 주의를 채워 넣지 않는다. 전체에 적용되는 조건과 가격 확인일은 필요할 때 한 번만 짧게 적는다.

## 완료 검증

작업을 시작할 때 요청된 전체 품목 목록과 품목당 필요한 비교견적 수를 먼저 고정한다. 사용자의 명시 요구 또는 적용 가능한 기관 기준을 따르며, 별도 지정이 없으면 작성 순서의 비교견적 2건을 기준으로 한다. `--expected-main`에는 확보한 일부 품목 수가 아니라 요청된 전체 품목 수를 넣는다. 일부 품목의 검증 성공은 전체 요청의 완료가 아니다. 수량·옵션 확인이 끝나지 않은 후보와 미확보 품목을 남기고 완료로 보고하지 않는다.

`비교견적 2부`는 본견적을 제외한 비교견적 2건이다. 붙임의 `각 1부`는 첨부 문서의 부수이므로 이를 거래처별 비교견적 수로 해석하지 않는다. 사용자의 요구나 적용 기준을 바꾼 근거 없이 초안·확보본의 건수에 맞춰 검사 인자를 줄이지 않는다. 같은 품목의 본견적과 비교견적은 각각 다른 판매처여야 하며, 같은 화면·판매처를 두 번 세지 않는다.

품목이나 수량 변경을 받으면 먼저 확정 목록을 갱신한다. 공문·세부운영계획서·활용계획서·구매내역·본견적·비교견적·검토용 모음의 해당 내용을 대조한다. 추가 품목은 금액표뿐 아니라 구매 목적·필요성·활용 내용에도 반영하고, 제외 품목은 본문·표·링크·캡처·합계에서 제거한다. 품목 종류 수, 포장 수, 주문수량과 물리적 총수량은 각각 의미에 맞게 적는다.

관련 서류를 함께 수정하거나 사용자 수정본을 넘겨받으면 [변경 대조 절차](references/revision-crosscheck.md)를 적용한다. 기준 목록과 위치별 대조 결과는 작업 기록에만 남기며 제출 문서의 비고란에 넣지 않는다.

동일 제품의 다른 판매처를 찾지 못했으면 확인한 범위와 남은 품목을 구체적으로 알린다. 다른 브랜드나 규격을 쓰려면 사용자가 그 비교 범위를 명시적으로 허용해야 하며, 허용된 경우에도 실제 브랜드·모델·구성을 그대로 표시하고 서로 다른 제품을 동일 제품으로 검증하지 않는다. 사용자 답변을 기다리는 동안 완료 가능한 품목의 캡처와 문서 검증을 진행한다.

완료 전에 [검수표](references/acceptance-checklist.md)를 적용한다. 이어서 다음 명령으로 편집 가능한 설명문, 순서, 수량, 총액 비교와 `글자처럼 취급` 속성을 검사한다.

```powershell
python scripts/verify_quote_hwpx.py "<최종.hwpx>" --expected-main <본견적수> --comparisons-per-main <품목당비교견적수>
```

명시적으로 허용된 유사제품을 포함하면 같은 검사에 `--equivalence-manifest <명세.json>`을 추가한다. 명세는 실제 수량·금액을 검사할 뿐 화면의 진위나 규격의 적절성을 입증하지 않으므로 원본 화면과 최종 출력의 시각 검수도 수행한다.

도우미는 모든 본문 구역에서 요구 건수, 품목별 연속 번호와 출처 문자열 중복을 검사한다. 같은 판매자가 다른 이름으로 표시되는 경우나 서로 다른 캡처가 같은 거래처인지 여부는 화면에서 별도로 확인한다. 유사제품의 차이는 해당 비교견적 설명문 뒤에 적어야 하며 다른 견적의 설명으로 대신 통과시키지 않는다.

스크립트 검사를 통과한 뒤 Kordoc, `python-hwpx`, `pyhwpxlib`, 설치된 한글 열기와 PDF 렌더링으로 정확한 최종 파일을 확인한다. 실제 출력에서 모든 캡처의 상품 사진·수량·총액·동일 제품 여부와 가독성을 직접 검사한다. 그림 개수가 맞아도 가격 화면만 들어 있을 수 있으므로 사진 존재를 구조 검사로 대신하지 않는다. 하나라도 확인되지 않으면 완료로 보고하지 않는다.
