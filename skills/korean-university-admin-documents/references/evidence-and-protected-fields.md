# Evidence and protected fields

## Evidence order

1. Explicit user instructions for the current deliverable
2. The exact current official form and current manual or notice
3. Current approved plan, register, quotation, roster, or source record
4. A known-openable derivative of the same exact form
5. A prior-year version of the same form
6. Similar documents only as structural examples, never as current factual evidence

## Population and affiliation evidence

Resolve the default department from the active task's working folder and its nearest department ancestor. A shared shell root or technical staging directory does not replace the task folder. An explicit user scope instruction takes priority; otherwise do not switch departments because another was discussed recently or supplied a reusable template. Record the working folder and resolved department, then check the people, companies, and output locations against that scope.

Before preparing a document per organization, reconcile the requested scope and every user-named person with current rosters. A single department's timetable does not establish a complete list across departments. Search results and previews route to records; inspect all relevant sections and original affiliation evidence before declaring an association absent. Keep a disposition for each scoped person: verified, conflicting, or unresolved after specified checks. Distinguish instructor/contact from legal representative, and deduplicate organizations separately from people. A user-supplied omitted name reopens the scope and requires rechecking the resulting list and affected documents.

Check each source's inclusion rule: parking applications and a single class schedule are partial lists. A user-corrected department and explicit person list replace the inferred scope, rather than adding departments to it. Use the confirmed names as an allowlist for the final list and every generated artifact, checking both omissions and additions. Keep excluded drafts outside active deliverables and preserve the original source records.

## Protected spans

For cooperation-report narrative inputs such as enterprise capabilities, inspect all sections of matching organization records before classifying a blank as unconfirmed. Summarize only recorded services or capabilities, preserve possibility/qualification wording, and avoid inventing results or agreed goals. Include each supported narrative value, or a specific source-checked reason for a blank, in the exact-cell field inventory and validate the saved report with `hancom-hwpx-documents/scripts/validate_hwpx_opensource.py --fields`. Successful opening and page counts do not establish field completeness. Preserve unrelated current user edits and signer-controlled inputs.

Protect names, organizations, titles, document numbers, dates, times, deadlines, amounts, percentages, quantities, units, URLs, email addresses, phone numbers, account information, identifiers, quotations, legal text, grounds, responsible parties, actions, conditions, exceptions, prohibitions, template labels, table geometry, row and list order.

Snapshot these spans before editing. After editing, compare value, count, association and order. If an invariant changes, roll back the affected output and report `VERIFICATION_FAILED`.

Do not infer missing vendors, prices, quantities, contacts, approval values, issue numbers, results or personal data. A previous document proves precedent, not the facts of a new transaction.
