# Procurement forms and evidence pages

Read this reference before drafting or revising purchase preapproval, expense settlement, vendor quotations, receipt attachment forms, or evidence-photo pages. Use the user's current edited files as the baseline. Keep active records in their working folder when the user requests that; organization is not permission to archive them.

## Permission and factual fields

- A request to prepare a document includes the user's clearance with the named vendor or party for that preparation and requested use of supplied names, seals, and signatures. Do not ask whether that permission exists or request it again.
- Treat dates, amounts, and party instructions supplied by the user as source facts. Distinguish missing business data from permission; inspect context and files before asking only for a value necessary to finish. Do not infer missing approval states or create an absent signature image.
- Use an existing supplied stamp or signature image when requested. Preserve its identity and proportions; do not draw, generate, or substitute a new seal. Preparation does not authorize sending or submission.

## Before filling the forms

1. Identify the exact current files, requested grouping, editable format, and supported source values. A later user edit overrides an earlier builder's cached text.
2. For the complete specification/quantity column, record one expression pattern: item-name repetition, specification-to-item association, specification and quantity, `등`, and whether an item/transaction count is requested. Apply `style-guide`'s narrow-column gate to every target row.
   Every item explicitly named in the adjacent material-name field needs its own supported specification and quantity. A uniform format that covers only the first named item fails. Repeating names in the quantity cell is optional when the quantities follow the adjacent names in the same order; apply that decision consistently. For a group spanning different specifications, aggregate only matching specifications or distinguish the subgroup quantities from the source.
3. Record each requested checkbox value and card identifier in the target-field map. A requested filled black box is `■`, not `□` or a tick mark; preserve every unrelated checkbox. Include the supplied identifier in the requested card notation. Keep its digits together if the card label and identifier need separate lines.
4. Identify the actual quotation date, preapproval date, purchase dates, inspection dates, and settlement date independently. Do not default quotation dates to the purchase date or today's date. When a quotation precedes preapproval, use the user's supplied actual date. File grouping by purchase day does not change the quotation's issue date.

## Quotations and receipts

- A calculation sheet does not replace a required quotation. When the user requests quotations, preserve the vendor form and create the requested quotation files. If Word is requested, keep item names, specifications, quantities, prices, and dates as editable DOCX text and tables; the supplied stamp can remain an image.
- Keep quotation issuer and actual purchasing merchant distinct. Reflect the actual merchant in receipt and settled expenditure records even when the quotation comes from another vendor. Reconcile unit prices, quantity, documented discounts, and final totals with the user's source records.
- When the user defines planned expenditure rows by quotation files, inventory every table that represents those planned purchases, including the official-letter cover table and attached operating plan. Apply the quotation row count, order, and amounts to all of those tables; updating only the attachment leaves the packet inconsistent. Merge component amounts belonging to one quotation and use the requested planned vendor where that field exists; do not retain receipt-merchant grouping in planned tables by habit. Preserve actual merchant records in the settlement evidence. Treat the quotation grouping as task-specific, not a fixed row count for later tasks.
- Apply only the draft/final filename and stamp state requested by the user. Do not add `시안`, caveats, a remarks column, or process explanations on your own.
- When receipt scans are item references and the user will attach originals, use the scans for supported item data. Leave the actual-attachment areas in the specified forms ready for the user; do not insert the reference scans as submitted receipts or add a manual-attachment note in the official document.

## Consistent evidence-photo layout

- Establish one grouping key and layout before placing images. For class evidence, use one class date per page or repeated section unless the user requests another grouping. Keep the class date and purchase/inspection date distinct.
- Prioritize purchased-goods overview and finished results. Add a representative process image between them or in a consistent smaller position when available. Use the same ordering, captions, and relative emphasis across dates; do not mix a whole-session collage on one page with unrelated individual-photo pages for other dates.
- Select representative images and avoid duplicate angles or unnecessary group photographs. Preserve source pixels and do not invent missing process photographs. When one date lacks a source for a category, omit that category while retaining the common goods-to-results order.
- Crop supplied collages only to isolate real source images. Preserve the original and verify the date and category association; low-resolution source evidence is not permission to generate a sharper replacement.

## Saved-file completion check

Inspect the exact saved file rather than only the builder inputs:

- Extract both the material-name and specification/quantity cells in row order. Compare every named item, its specification, physical quantity, and the chosen name/`등`/count pattern against the source. One named item without its quantity is a failure even when the format and total match. Required values may not be replaced with a reference phrase; no rejected count suffix may remain. Check ordinary wrapping and legibility rather than squeezing long cell text onto a single line.
- Compare every target checkbox and payment field to the requested state. Verify the complete card identifier in the readable page image; correct aggregate text does not excuse digits split across lines.
- Compare quotation issuer, issue date, item lines, discounts, and total to their sources and keep the actual merchant in payment records. Verify DOCX text is selectable and editable rather than a flattened page image.
- If planned purchases are grouped by quotations, extract each planned table's data rows after saving and compare its row count, row order, and amount vector with the requested quotation list and the other planned tables. Check planned vendors wherever that field exists. An aligned operating plan does not pass when the official-letter table still has the old grouping, even if both totals agree. Recompute each merged amount and the overall total; verify receipt evidence retains its separate actual-merchant associations.
- Compare photo captions and image sources date by date. Verify goods and results are readable and prominent, process images follow the same layout, and no image has changed date/category.
- Compare all changed remarks, attachment, and narrative cells to the source and authorized scope. Remove agent-added explanations and status notes; preserve mandatory template wording.
- Confirm the user's latest edits and grouping survive, and no unrequested archiving or extra PDF delivery occurred. Create PDFs only for a request or confirmed printing/submission need; keep minimum verification-only PDFs outside the active records folder.

Failure in any target field or association blocks completion even if amounts, XML parsing, or page counts pass. Keep the field map and comparison results in technical work records, not in the official form.
