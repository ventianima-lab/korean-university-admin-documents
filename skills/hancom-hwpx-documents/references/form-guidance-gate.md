# Annotated original authority and guidance gate

## Failed path and authority split

A modified predecessor had already replaced an official table with free prose and pruned anchored writing notes. Copying that predecessor or retaining an uninspected original did not establish original-form fidelity. The **current annotated official original** controls structure, merged cells, fixed labels, fonts/spacing and instructions. The **latest live filled document** controls retained current content within the requested edit scope. Inspect both roles; never inherit a predecessor's layout change as permission. A fixed example or placeholder is not evidence of an actual value.

Before authoring, independently review all source guidance channels and anchors: visible inline guidance, nested MEMO/comment controls and text, linked field ends, raw XML comments and relevant package parts. Body Markdown or a recursive list of all `hp:t` nodes is not exhaustive guidance review or a reliable visible-body extraction. HWPX MEMO `fieldBegin` instructions may live in nested `subList`/`hp:t`; parameters such as author, timestamps and command IDs are metadata, not the instruction. Exclude the entire MEMO subtree from visible-body text and review its actual text separately. Inspect drawing/image-only instructions visually when applicable; this XML helper cannot OCR or verify those.

Keep the blank original and source pack fully annotated. For a filled copy, follow each actual source instruction's applicability and exact scope: fill, preserve, or remove an explicitly inapplicable block/comment. A programme-specific content instruction does not authorize rebuilding tables, dropping merged cells or changing fixed fields. Never apply a blanket comment-removal rule. Document an explicit user exception as such without inventing a source instruction. Respect all user-reserved content/fields and review waivers.

## Commands and scope

```text
python <skill-dir>/scripts/verify_form_guidance.py --inspect <original-annotated.hwpx>
python <skill-dir>/scripts/verify_form_guidance.py --inspect <active-blank-or-authorized-candidate.hwpx>
python <skill-dir>/scripts/verify_form_guidance.py --spec <private-guidance-spec.json>
python <skill-dir>/scripts/verify_form_source_pack.py --inventory <private-inventory.json> --pack <private-pack.json> --active-dir <event-folder> --guidance-check
```

Inspection returns `UNREVIEWED`, never clearance. It enumerates every meaningful raw XML text/tail in XML/HPF/relationships parts, controls/memo/comment observations, reference candidates, XML comments, node paths/fingerprints and separate `visible_body_text` excluding MEMO subtrees. Reference candidates are mechanical IDRef matches, not semantic proof of an anchor. All observed source text/annotation IDs need independent classification and decisions, including explicit out-of-scope dispositions for other forms in a manual. Do not generate a passing decision map merely from the output file list or by auto-labeling every observation as metadata.

`--guidance-check` requires each mapped HWPX blank's `forms[].guidance_spec` absolute path. The source-pack checker binds its original and target paths to the independently inventoried official source and active blank, requires `stage: "blank"`, and retains the active-copy/hash/full-role gate. Without the flag, the result explicitly has `guidance_checked: false` and proves no annotation fidelity. Non-HWPX sources require a source-faithful inspectable conversion plus independently reconciled authority or an explicitly reported equivalent review; do not pretend an unreadable binary source passed XML comparison.

## Guidance spec v1

Top-level keys:

- `schema_version: 1`, `source` (absolute annotated official HWPX), `source_sha256`, `target` (absolute blank or authorized candidate), `stage` (`blank` or `filled`). These roles may use the same existing official file only in blank mode. Source authority is independently selected, never inferred from a predecessor's successful parsing.
- `regions`: nonoverlapping source-to-target mappings `{source: {part, path}, target: {part, path}}`. Paths are zero-based XML child-index arrays, including XML comment nodes; `[]` is the part root. Use the actual inspected part, not an assumed section number. Either side can add `children: [ascending unique child indexes]` to select a source paragraph sequence from a larger section while comparing it with a standalone target section. Declare the complete source-form scope independently, including labels, tables, inline guidance and anchored controls, not only convenient cells.
- `text_reviews`: every observed text ID maps to `{id, classification, reason, instruction_ids}`. Classification is `guidance`, `label`, `placeholder`, `value`, `metadata` or `out_of_scope`. Every guidance row needs instruction IDs whose `evidence_ids` contain that exact text ID. Selected nested MEMO `hp:t` instructions cannot be dismissed as metadata. Inline writing directions need guidance decisions too; the helper cannot semantically distinguish a mislabeled direction from a label.
- `annotation_reviews`: every observed annotation ID maps to `{id, reviewed: true, classification, reason, disposition, target_id, instruction_ids}`. Classification is `instruction`, `metadata` or `out_of_scope`; disposition is `preserve`, `delete` or `out_of_scope`. An instruction needs linked decisions whose evidence includes the exact annotation ID. Preserve maps to an actual target observation with the same canonical fingerprint after only the exact source-authorized descendant edits/deletions (blank mode permits none); target IDs may move after authorized deletions, so inspect the candidate instead of guessing. A selected or mechanically anchored annotation cannot be ignored. Deletion needs the actual source-directed exception below; blank mode forbids it.
- `instructions`: `{id, evidence_ids, applicability, permission, action, scope, reason}`. Evidence IDs come from original inspection. Applicability is `applies`, `inapplicable`, `out_of_scope` or `unresolved`; unresolved blocks. Permission is `content_only`, `delete_block`, `delete_annotation` or `retain`; action is `fill`, `delete`, `preserve` or `not_applicable`. Scope is a nonempty list of exact original `{part, path}` locations. The independent reviewer must justify the source condition and authorized scope; a claimed permission is not authenticated by the helper.
- `text_edits`: filled-only `{source: {part, path}, old, new, instruction_id, content_evidence}`. The exact source leaf text must match `old`; only independently classified placeholders, values or replaceable guidance may be filled through a scoped `content_only`/`fill` instruction. Fixed-label/metadata edits fail. Supply actual current source/user evidence for `new`, rather than treating an example as a real value. For a legitimately retained value equal to the example, an evidenced `old == new` mapping accounts for it explicitly. A selected placeholder in filled mode must be accounted for by an edit, an authorized containing deletion, or `disposition: "preserve_fixed_example"` linked to a `retain`/`preserve` instruction.
- `text_insertions` (optional): filled-only `{parent: {part, path}, new, instruction_id, content_evidence}`. Permit only one `hp:t` leaf in a genuinely childless original `hp:run`, within the independently mapped field and a scoped `content_only`/`fill` instruction. Keep its original run properties. This represents an actual blank input that has no pre-existing text leaf; it does not permit inserting paragraphs, tables, controls, new fields or changed formatting. Blank mode forbids insertions.
- `deletions`: filled-only `{source: {part, path}, instruction_id}`. Only exact source-directed `delete_block` or `delete_annotation` scopes can delete nodes. This includes separately mapped heading/label blocks, conditional tables and associated MEMO `fieldBegin`/`fieldEnd` or formula controls when actually authorized; a content-edit permission cannot do so. Map every affected node/paired control independently. Never delete a whole mapped form. Applicable fill/delete decisions must actually be applied, not merely listed.
- `content_authority`: filled-only `{kind: "live_filled" | "user_facts", path, basis}`. A live-filled authority needs its current absolute path and why it is the latest content baseline; the helper does **not** read or hash that live file. It does not establish that the proposed content really preserves it: independently compare the requested fields and respect concurrent user edits.
- `extraction_openers` (optional): `{source_parts: [{part, path}, ...], target: {part, path}, reason}`. The source parts must be unique original `secPr`/`colPr` subtrees or an exact `ctrl` containing only one `colPr`. Preserve the actual original wrapper: never flatten `ctrl(colPr)` into a direct property. Only a target run containing those exact ordered subtrees plus an optional empty text node may be ignored as an independent-section opener. Page/start counters remain exact, including zero values. The run must preserve its actual original donor-run attributes (only `charPrIDRef` is accepted). Independently compare its referenced style/font definitions before removing it from the body comparison; then compare body styles without counting a donor-only style as an added business-content style. This is not a general layout exception. State the actual source property transfer; preserve page/column settings and check native pagination separately.

Use empty `text_edits`, `text_insertions` and `deletions` in blank mode. Keep manifests, raw source instructions, author metadata and actual inspection outputs in the existing private technical evidence, never public fixtures or unsolicited deliverable sidecars.

## What is checked and what remains independent

The comparison requires all declared raw-text/annotation reviews and scoped instruction evidence. It compares each selected original subtree after **only** the listed authorized text edits/deletions, and fails on changed/missing tables, cell addresses/spans/sizes, fixed labels, styles or other protected XML. It resolves referenced char/paragraph/style/border-fill definitions and font-face fingerprints, so equal numeric style IDs alone cannot clear changed fonts or spacing. Only whitespace-only serialization, `linesegarray` caches and dirty/text-extent caches are ignored. Exact source-bound section openers have the narrow exception above. A benign native reserialization may still fail conservatively; report or independently verify that precise difference instead of widening exclusions to tables or fixed fields.

When the user explicitly requires retaining current formatting that differs from the official original, do not normalize that user formatting to manufacture a PASS or mask an entire style. If a strict original-style validation view is used, bind its exact hash and prove an independent bridge to the actual normal pre-color candidate: identical text/tables/merges/fixed labels and all other properties, with only the precise user/source-evidenced property changes at the exact fields. Resolve actual font family/size/weight, paragraph settings and input colors, rather than assuming equal IDs mean equal styles. This helper does not verify that bridge; report the remaining limitation unless an independently scoped exact-difference check establishes it. The subsequent red gate must start from the actual normal pre-color candidate, not the original-style view.

For authorized red assumption marking, pass the **pre-color candidate** against the annotated original first. Freeze that exact candidate, then use the existing independent red-span gate to bind the final colors to the unchanged pre-color text, fonts and structure. Red style clones are not grounds to weaken the original-form/font comparison.

This checker cannot authenticate official status, guarantee that the selected form regions are exhaustive, interpret a condition or permission, prove substantive detail is sufficient, validate page count/current rendering, or prove source evidence for actual values. Native layout and content review remain separate when authorized. Preserve actual sequence: a later repair/check never becomes proof that the gate ran before earlier authoring. An independently performed manual-first comparison may be reported separately; formal checks run when actually executed and before promotion, not retrospectively. A post-edit QA waiver continues to control actual saved documents.

For changes to these helpers, exercise the actual `--inspect`, `--spec` success/failure JSON-and-hash reporting, and source-pack `--guidance-check` CLI paths as well as the imported comparison functions. Passing an imported comparison alone cannot establish that the reporting/serialization path works.
