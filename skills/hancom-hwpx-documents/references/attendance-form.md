# Attendance-sheet reference

Identify the current responsible-office official attendance-sheet blank, version and role first; do not substitute a user-supplied filled record, remembered local path or generic template for that search.

Treat the selected master as read-only unless the user explicitly requests an edit to that exact file.

For institutional authoring, bind current official structure and retain its visible source pack before consulting this historical visual/content reference. Only an explicit current-task instruction selecting another structural master instead of the official form permits that exception. A latest live user-edited sheet remains the protected baseline for scoped revisions; this rule does not authorize rebuilding it.

When the user asks for a similar attendance form, after resolving that authority:

- inspect the current master at task time rather than relying on remembered numeric geometry or color values;
- preserve its exact page orientation, margins, title placement, information table, main-table dimensions, cell fills, character styling, fonts, spacing, borders, and line weights;
- copy and adapt it only after explicit authorization to create a document;
- change only requested text, dates, participant data, and other explicitly requested fields;
- do not create normalized or shade-adjusted derivatives merely because the master’s design is discussed.

The master file itself, not this note or a generic style constant, decides the visual appearance.

## Establish event membership before copying roster cells

A meeting roster is a layout source, not proof that its attendees also attend a lecture, evaluation, or other activity. Programme responsibility, a budget's refreshment headcount, and a person's inclusion in another activity do not establish attendance. Before populating names, resolve the target activity's attendee set from explicit user instructions or an activity-specific roster, independently of the template. If a role's attendance is unsupported, do not add that person merely to match a budget count.

Build the expected roster from that independent source before checking the saved cells; copying the template's names into the expected inventory is circular validation. When an attendee is excluded, remove the corresponding name, role/ID, and affiliation from every affected session, close the numbering gap, and refresh package previews while preserving unrelated sessions and costs. A correction to attendance alone does not authorize changing refreshment budgets or other activity rosters. If the user explicitly reserves review, make the narrow edit and disclose that document review was not performed rather than running a separate review pass.
