# Authorized red marking of unconfirmed choices

Use this gate when a current request or standing user instruction asks to mark the assistant's unconfirmed choices red; the standing instruction is sufficient and does not need repeated permission. Apply the shared [complete-authoring policy](../../submission-ready-authoring/SKILL.md). Before entering or coloring values, independently inventory every requested input and map its source, explicit user approval, or assistant selection/inference. Review the complete inventory against the source form and latest user instructions. Color only exact characters of assistant-selected or inferred drafting choices that remain unconfirmed. User-confirmed values, independently verified facts and calculations, and fixed template wording keep their applicable original colors, including blue; do not normalize them to black. Calculations with assumed inputs remain unconfirmed. Red is a visual flag, not evidence or authorization to invent signer-controlled, consent, approval, outcome, or other unsupported external facts.

Do not append explanatory status labels to the document or filename unless requested. Preserve the official form, body, separators, paragraph and table layout, styles, and signatures; do not remove a template's own required wording. Keep the source mapping and unresolved issues in a private record or report. Inspect the final native render for exact placement and readable red text.

For a text-only edit, first verify the edited **pre-color** candidate against the authoritative source using `verify_form_text_edits.py` and its independent inventory, or an equally strict separately reviewed preservation method if the text-only helper cannot handle the source. Save and hash that pre-color file. After applying red, run:

```text
python scripts/verify_red_assumption_spans.py BEFORE.hwpx AFTER.hwpx PRIVATE_INVENTORY.json
```

The inventory is private, independently prepared before entering/coloring values, and reviewed for completeness. Bind it to exact pre-color and final bytes with `before_sha256` and `after_sha256`; `red_instruction` identifies the user's current or standing instruction. Set `red_instruction_scope` to `current_request` or `standing_preference` (omission preserves the legacy current-request format); neither value authenticates the cited instruction. `red_color` is the requested red `#RRGGBB` (for ordinary red use `#FF0000`). `values` is the independently sourced list of input values, with the exact saved text and provenance. Each entry uses `section` (for example `Contents/section0.xml`), zero-based `paragraph` among all `hp:p` elements in document order including table/nested paragraphs, and zero-based Python Unicode character offsets `start` inclusive and `end` exclusive in that paragraph's direct run text. Specify `text`, nonempty `evidence`, and `provenance`: `assistant_unconfirmed`, `user_confirmed`, `verified_fact`, `verified_calculation`, or `fixed_form`. Do not derive the expected source classes or offsets solely from the colored output; review the mapping against the actual independent sources.

The helper compares all section paragraph text and form structure, resolved character properties (including font references), header font definitions, and non-preview package parts. Only red within `assistant_unconfirmed` spans is permitted; other text retains its pre-color color and all text retains its other character properties. Existing red fixed text is preserved. A missing red character, spill, stale hash, altered font, unapproved form change, unsupported inline text control, or unsupported run structure fails closed. Roll back the affected candidate to its verified baseline and repair it; do not widen the permitted colors to pass. Some harmless native serialization or inline controls may require a separate independently reviewed check; never treat a failure as a pass. The helper cannot prove the inventory is exhaustive, that a source is authoritative, that a selected value is appropriate, or that previews and rendering are current. Independently verify those limits and the exact final file; preserve its baseline and do not publish private inventories.
