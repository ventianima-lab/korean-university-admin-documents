# U-ERP 수입·지출결의

## 조회와 대상 확인

1. 사용자가 지정한 U-ERP 세션과 브라우저를 사용한다. 기존 탭을 기록하고, 입력 중인 탭에 미저장 변경 경고가 나타나면 그 변경을 유지한다. 별도 작업 탭에서 조회하고 작업 탭만 닫는다. 브라우저 제어권이 사용자에게 넘어가면 재개 요청을 기다린다.
2. `예산회계 → 부서회계업무 → 결의서관리`에서 `수입결의서` 또는 `지출결의서`를 연다. 회계연도·회계단위·회계구분을 먼저 대조한다. 결의번호를 알면 번호로 조회한다. 화면에서 조회 형식이 구분자 없는 번호라면 해당 형식으로 입력한다. 번호가 없으면 `결의번호조회`에서 날짜 범위와 예산부서를 확인하고 검색한다. 예산부서 기본값이 다른 부서면 검색창에서 부서명과 코드를 맞춘다.
3. 결의번호·부서·제목·금액·상태를 확인한다. 같은 사업과 결의 유형의 이전 결의는 결의내용과 첨부의 선례로 읽는다. 이전 금액·계좌·대상자·결재 정보는 이번 건의 증빙에서 확인한다. 기존 건을 수정하라는 요청이면 해당 번호를 다시 열어 필요한 필드만 수정한다.

## 수입결의

- 입금 증빙에서 입금일·입금 주체·실제 금액을 확인한다. 회계구분·사업·계정과목·수단은 해당 건의 현재 근거와 화면을 대조한다. 실제 입금, 결의일, 입금 예정일, 배정예산은 서로 다른 값이다. 예산잔액은 같은 범위의 ERP 화면에서 확인하고, 화면 값과 원자료가 어긋나면 완료 보고에 적는다.
- 사용자가 지정한 이전 결의의 문단·줄바꿈·들여쓰기·붙임 구조를 따른다. 관련근거와 붙임에는 동일 공문의 제목·문서번호·시행일을 정확히 기재한다. 입금 통보 공문이 없어서 사용자가 학과 발신 공문을 사용하도록 지시했다면 그 공문으로 작성한다. 본 통보 공문이 도착해 교체할 때는 관련근거, 붙임 문구, 실제 첨부를 함께 바꾼다. 입금 증빙은 보존한다.
- 대상자 기재가 필요하면 이번 명단에서 해당 기관·부서의 인원·소속·지급액을 대조하고 합계와 실제 입금액을 비교한다. 명단에 없는 학번은 같은 사람으로 확인된 내부 신청서에서 가져온다. 여러 기관의 명단은 조회 범위 밖의 개인 정보를 저장하거나 첨부하지 않는다. 암호가 있는 명단은 [스프레드시트 첨부 접근 절차](../spreadsheet-form-preservation/SKILL.md#attachment-access-and-compatibility)를 사용한다.

## 지출결의

- 동일 유형의 이전 지출결의를 조회해 제목·결의내용의 항목 순서, 단락, 구분선, 빈 줄, 붙임과 증빙 구성을 확인한다. 이번 건에서 승인된 구매·거래·검수·지급 증빙으로 실제 금액, 계정, 거래처와 증빙을 독립 대조한다.
- 증빙은 현재 결의에 해당하고 첨부가 허용된 것만 등록한다. 거래처나 계좌의 신규 등록은 결의 저장과 별개의 변경이므로 현재 요청에 해당 등록이 포함된 경우에만 진행한다. 등록 여부, 계좌 승인, 결의 상신과 지급을 각각 화면에 표시된 상태대로 보고한다.


## 예산잔액 초과와 추경 조회

- 지출 저장 경고에 표시된 계정코드를 기록한다. 결의번호가 생겼는지 별도 탭에서 다시 조회한다. 화면의 작성 상태나 저장 확인창만으로 저장을 판정하지 않는다.
- `예산회계 → 부서예산업무 → 예산현황 → 예산집행현황조회`에서 회계연도·회계단위·회계구분·수지구분·예산부서를 맞춘 뒤 같은 사업·계정 행의 전체편성예산·집행·잔액을 비교한다. 같은 조건으로 `추경예산편성현황`의 실제 반영 내역을 확인한다. 은행 입금과 수입결의는 지출 예산 배정을 입증하지 않는다. 부족한 예산을 피하기 위해 다른 계정으로 옮기거나 금액을 임의로 줄이지 않는다.
- `예산회계 → 부서예산업무 → 예산신청 → 추경예산신청`의 신청 입력, 제출, 승인 후 예산 반영은 각각 별도 단계다. 현재 차수와 대상 부서 등 입력 조건을 확인하고 신청 목록에서 중복을 점검한다. 동일 사업 선례에서 수입·지출을 각각 신청한 경우에는 현재 지침과 양쪽 계정을 확인한 뒤 같은 금액을 각각의 수지구분에 매핑한다. 회신기한이 있으면 요청과 반영 확인의 일정 판단에 사용한다. 조회나 오류 진단 요청만 받은 경우에는 신청을 저장하거나 제출하지 않는다.

## 추경예산 신청과 임시저장

- 전례는 `예산신청현황조회 → 신청번호 편성내역`에서 회계연도·회계단위·회계구분·예산부서·예산구분을 맞춰 찾는다. 신청번호를 열어 차수, 수지구분, 사업코드, 계정코드, 금액, 처리상태를 확인한다. 이전 확정액과 이번 증액 요청액은 별도 값이다.
- 임시저장 권한이 있는 경우에만 `추경예산신청`에서 부서와 회계 조건을 맞추고 필요한 수지구분별로 신규 작성한다. 기편성현황에는 있는 사업이 신규 신청의 사업 검색에 나오지 않으면 검색 결과만으로 사업 미등록을 판단하지 않는다. 신규 화면의 `본예산선택입력`이 켜진 상태인지 먼저 확인한 뒤 기존 빈 사업 행을 사용한다. 빈 행이 없을 때만 사업계획서의 행을 추가한다. 그 행의 사업 검색창에서 정확한 코드를 입력하고 조회를 눌러 선택한다. 선택한 사업 및 상세 계정의 코드와 수지구분을 확인한다.
- 상세내역의 `예산신청내용`에 근거 있는 내역을 입력한다. `산출근거 입력` 창에서 행을 추가하고 계산식을 기재한 뒤 Enter로 자동 계산된 금액을 대조한다. 확인 후 상세내역의 신청예산이 일치하고 빈 사업 행이 없는지 확인한다. 해당 화면의 `저장`으로 임시저장한 뒤 신청번호와 처리상태를 확인하고 `예산신청현황조회`에서 다시 조회한다. 화면상의 임시저장은 제출·승인·예산 반영이 아니다. 제출이나 다른 상태 변경은 해당 작업을 명시적으로 요청한 경우에만 진행한다.

## 비고와 출력물 확인

- [비고 입력 규칙](../submission-ready-authoring/SKILL.md#remarks-default-to-blank)을 적용한다. U-ERP 수입결의서 출력에서는 `증빙정보 → 내용`에 저장한 문구가 증빙표 `비고`에 찍힌다. 화면의 입력란 이름이 `비고`가 아니어도 같은 규칙을 적용한다. 허락받기 전에는 특별한 경우의 제안도 완료 보고에만 적는다. 증빙 구분·건수·금액 등 다른 필드는 그 필드의 실제 요구에 따라 처리한다.
- 작업 전 기존 입력값을 확인하고, 미리보기에서 증빙표 비고와 본문·계정별 적요를 구분한다. 출력 검수가 가능하면 해당 결의의 `출력` 미리보기에서 비고와 첨부 목록을 확인한다. ERP 양식의 글자 크기를 이유로 설명을 줄이거나 더 작은 글씨로 밀어 넣지 않는다.

## 저장과 재조회

1. 긴 결의내용은 입력란을 클릭하고 전체 선택되었는지 확인한 뒤 붙여넣는다. 포커스를 옮겨 반영하고 저장 직전 전체 문자열을 대조한다. 새 문구가 기존 내용 앞에 덧붙는 경우에는 원문을 복구하고 전체 선택부터 다시 한다.
2. `관련첨부파일`에서 파일을 추가한 뒤 파일관리 창의 `저장`을 먼저 누르고 `확인`한다. 교체할 때는 새 파일이 다운로드 가능한 상태인지 확인한 후 대체된 파일만 목록에서 제거하고 저장한다. 사용자가 수정하지 말라고 한 원본과 다른 첨부는 유지한다. 파일관리의 `확인`만 눌러 생기는 미저장 경고를 저장 확인으로 취급하지 않는다.
3. 결의서 자체를 `저장`하고 정확한 결의번호를 다시 조회한다. 저장된 본문 전체와 줄바꿈, 금액, 부서, 표시 상태, 첨부 수·저장된 파일명을 대조한다. 본문 대조에서는 필요하면 CRLF와 LF만 같게 본다. `작성` 상태의 저장은 해당 상태로 보고한다. 결재 상신·발송·지급·다른 회계 처리에는 별도의 사용자 요청이 필요하다.

검증을 마친 실작업에서만 절차를 보강한다. 절차에 실제 결의번호·학생 또는 거래처 정보·계좌·문서 원본·인증정보를 남기지 않는다.
