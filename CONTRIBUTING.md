# Contributing

Contributions should improve repeatable university administrative-document work without embedding one institution's confidential procedures or real records.

1. Keep `SKILL.md` concise and move conditional detail into `references/`.
2. Add scripts only when deterministic execution materially improves correctness.
3. Use synthetic fixtures and examples.
4. Preserve upstream license and attribution metadata.
5. Run `quick_validate.py` for each changed skill and test changed scripts.
6. Scan the tree for secrets, personal paths and real institutional data before opening a pull request.

## Maintainer synchronization policy

Document-skill updates are complete only after their public-safe changes are validated, committed, pushed, and verified on the remote repository. Compare complete installed skill folders, including scripts and references, rather than only the current conversation's edits. Retain public-only adapters and newer public corrections. Generalize personal paths and private institutional context; never publish real records or redistribute proprietary plugin material without permission. Record intentionally retained differences and any publication blocker instead of claiming complete synchronization.

## User corrections become skill improvements

Every user correction or report of an agent error triggers a relevant skill improvement in the same task, without requiring a separate skill-update request. Repair the authorized deliverable when necessary, then preserve the verified cause, prevention rule, and a meaningful completion check in the existing skill that covers the workflow. If the rule already existed, strengthen the failed invocation, helper, or verification path rather than adding a duplicate reminder.

Keep the change narrow and evidence-backed. A corrected reference can update the skill without authorizing edits to that reference or unrelated records. Preserve the user's file, document grouping, latest edits, and requested scope. Use the skill-creator workflow, preserve invocation metadata and unrelated resources, validate changed skills, and test changed executable helpers. Synchronize all public-safe document-skill changes under the maintainer policy above; report concrete blockers instead of claiming completion for a local-only patch. Private facts, secrets, temporary state, and unverified workarounds do not belong in the public skill pack.
